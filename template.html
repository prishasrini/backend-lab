Idempotency keys

The first request with a key does the work; any repeat gets the saved response back. A different body with the same key is rejected with 422.

Row locks

Wallets are locked in a fixed order while a payment runs, so five payments at once can't spend the same rupee twice, and can't deadlock.

Double-entry ledger

Every movement is a debit and a credit summing to zero. The audit recomputes each balance from the ledger.

The unsafe button

It reads the balance, waits, then writes without locking. Parallel requests overwrite each other (a lost update), and the audit catches it.

Exact ground truth
Every incident is a failure injected on purpose, so the right answer is known for certain, unlike real incident archives.

    
Paired conditions
Each incident is shown four ways with identical metrics. Only the logs change, so any accuracy drop is caused by log quality alone.

    
Confusable faults
A bad release and a full disk both break checkout with 500s; a slow database and a busy CPU both add latency. Telling them apart takes real reasoning.
